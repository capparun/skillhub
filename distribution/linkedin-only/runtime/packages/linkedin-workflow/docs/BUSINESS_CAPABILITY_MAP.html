业务之间如何组合

客户开发：账号检查 → 目标公司发现 → 公司研究 → 找关键人员 → 背景研究 → 筛选名单 → 触达准备 → 获准执行 → 关系跟进

招聘寻访：账号检查 + 已确认岗位要求 → 人员发现 / 公司人才地图 → 经历核实 → 最终名单 → 旧招聘 Outreach 审批与执行 → 沟通状态

职业与机会研究：职位机会研究 → 公司与相关人员研究 → 模型分析 → 研究报告；需要联系时再进入触达流程

内容与影响力研究：动态 / 帖子读取 + 可见指标 → 模型分析主题与表现 → 报告和建议；不包含自动发布

精确对象任务：已有公司、人员或职位链接 → 直接研究对应对象 → 输出，不要求先搜索。

所有业务共享的支撑，不额外制造业务步骤

账号与权限按普通账号、Premium、SalesNav、RPS 分类；RPS 尚未开发。身份与具体操作权限分别检查，能力未知先核实。遇验证、限流或未知执行结果，停止依赖动作，不自动换路绕过。
模型与平台分工模型决定标准、路径、匹配、内容和下一步；平台按明确参数返回事实与执行回执。行业、国家、目标数量均为任务参数。
进度与交付分页覆盖、去重、预算、回执复用、失败恢复、授权和防重台账。用户交付为 HTML 表格 / CSV；PDF 独立导出。

现有统一任务 CLI：task-create / task-validate / plan / task-execute / task-status / task-company-people / task-assess / task-report / task-resolve。task-prepare-outreach 可准备本地交接；不代表发送授权。普通搜索误判已修复并小样本实测；经历读取已实测，项目读取仍未实测；本图更新不代表代码交付完成。

范围：当前可访问项目中的 LinkedIn 相关 Skill、命令与脚本，不代表 LinkedIn 网站全部产品功能。40 条命令审计 · 能力契约与使用手册。静态完整展示，无折叠交互。
