# 开发效率复盘与后续执行约束

本次复盘由用户指出浏览器标签页过多触发。结论：有明显的重复工作和资源管理缺陷，责任在开发设计与验收编排，不能归因于用户需求变化。

## 已核实的问题

| 问题 | 证据 | 影响 |
| --- | --- | --- |
| 会话创建后未回收 | 各操作通过随机 UUID 新建浏览器 session，缺少 finally 关闭；现场清单曾有 19 个测试标签，其中 10 个为重复设置页 | 占用用户浏览器、内存及操作焦点 |
| 完整账号检查重复过多 | dev.7 的一次业务运行使用 207 次 OpenCLI 调用；10 个操作均进入完整 account-check，包括重复读取套餐/余额 | 有效业务查询和详情预算被前置检查占用 |
| 技术验收与业务验收顺序颠倒 | dev.6 的业务双跑暴露动态选项计数、长输入快照截断、单页分页布局问题 | 修复后又重启业务验收，反复产生相似页面与回执 |
| 回放层次定义过晚 | 最初辅助器注入 transport 的读取结果；后来才补正式 CLI + 实际浏览器 DOM 回放 | 早期函数测试不能作为完整受控链路证据，需要补跑 |
| 测试基础设施预检不足 | 临时辅助器曾出现语法错误；CLI 入口编辑也曾把 import 放到 shebang 之前，离线测试暴露后修复 | 与平台无关的错误消耗调试时间，应该在运行浏览器前发现 |
| 证据台账没有及时收敛 | 状态文档并存“正在运行”与历史结果，未清晰区分候选版本、开发者复现与独立验收 | 容易重复执行已有证据，用户难以判断真实进展 |

207 次是本地工具调用，不是 LinkedIn 官方消耗额度。10 次完整检查依据实际命令轨迹与生产调用关系核对；不得把估算的内部调用拆分写成实测节省。

## 已实施的资源修复

- 单次 CLI 命令的账号检查、选项、搜索或详情操作共用一个本命令拥有的 session。
- 通过 finally 回收该 session；不接管用户绑定的页面进行清理。
- OpenCLI 默认 close 仅释放租约，因此仅对关闭子进程设置 `OPENCLI_CLOSE_OWNED_TAB=1`，要求实际关闭本命令拥有的标签。没有修改全局配置。
- 打开页面前在总 request_budget 中预留一次关闭调用；预算不足则不创建页面。业务预算耗尽也可回收。
- 清理失败单独返回状态及 session，不重做业务操作，也不掩盖原业务失败。
- 离线回归 105 项通过。真实前后标签清单已核验：一次账户检查后无新增遗留标签，扩展确认自有 session 已关闭。旧测试分组已清空，保留一张普通公司页与原新标签页。

会话回收修复解决标签增长。后续开发源码又加入五分钟能力快照和逐次自有 URL 核对；受控CLI的单公司读取由16次降至9次，未将该数字外推为真实站点或整轮寻访的节省。

## 后续账号检查优化边界

完整能力检查、账号身份核对、目标页面就绪检查必须拆开：任务开始做完整检查；同一受控执行上下文的后续步骤只做必要的身份与目标页面验证。套餐及 InMail 余额不应每次只读查询都重新读取。

复用必须绑定明确 Profile、自有资料 URL、所需能力及有效期。账号切换、绑定不一致、登录/验证、目标能力拒绝访问或过期后立即失效。不能仅缓存显示名，也不能把一次可用当成永久授权。实施后以同一业务轨迹比较调用数，未完成前不宣称节省比例。

## 调整后的开发与验收顺序

1. 本地语法检查、CLI 契约与适用单元测试先通过；测试夹具先执行最小 smoke。
2. 异常及边界在受控浏览器回放；明确 U/I、R、L 的证据范围。
3. 按字段矩阵做定点真实验证，连同会话/预算/恢复链路完成技术验收。一次操作只解决一个尚无证据的问题。
4. 技术链路稳定后才固定候选包，执行已批准的五个业务场景各独立两次；同一 Profile 串行。
5. 发现缺陷先复现并补回归测试，修复后先跑受影响项。只有影响业务契约或固定候选验收结论时，才重跑相关独立业务用例；不机械重启所有场景。
6. 最终仍按完整 PRD/E2E 门槛审计。减少重复执行，不删掉必需字段、异常、独立双跑或安装首次任务的验收。

源码同步不等于发布；通过部分功能或没有合格业务候选，也不等于完整验收失败或成功。技术断言、模型行为断言和现实数据缺口必须分列。

## 当前未完成事项

跨命令能力快照与逐次身份核对已在开发源码实现，受控CLI调用由16次降到9次；真实站点性能及新候选交付仍待验证；完整字段矩阵和全部独立业务场景尚未验收；未知模态弹层的公司读取受控链路已修复并验证，搜索分支的完整异常断言仍需补齐。继续开发时先补这些缺口，不再一边扩大真实业务运行一边修基础链路。

## 字段联测发现：动态页面上的展开目标

组合公司查询的真实回执显示，语义展开点击返回成功并发生 `reidentified`，但目标字段没有展开，之后输入报 `selector_not_found`。该次失败保留在本地真实回执中，不计入通过。修复为从当前 DOM 精确匹配唯一可见的展开按钮并返回 CSS 定位，避免语义名称转换成旧快照引用；仍保留后续查询条件校验。离线回归 117 项通过，真实受影响组合需单独重测；旧候选包不因此升级。

空白套餐设置页不再直接推翻此前的首页/公司/人员搜索证据：只对明确的同URL空壳启用精确自有资料URL再核验，套餐与余额仍unknown。设置页登录、其他账号、恢复时自有URL变化继续停止。此修复针对真实联测的加载失败，不通过重跑业务场景规避问题。展开解析与点击拆成两个预算可见调用。

## 动态候选的输入前空轮询

人员字段联测的多选查询在本地120次预算耗尽时仍处于设置条件阶段，页面已回收，失败证据保留。离线复现证明：两个动态字段在尚未输入用户条件时分别等待7次默认候选，总计14次无效等待。修复为先确认展开/输入表面就绪，读取一次默认列表；无精确候选且支持输入时直接填入，再轮询实际响应。没有放宽精确标签、歧义、模式或完整查询后置断言。122项离线测试通过；人员多选仅重测这一受影响用例，已通过的单选/更换记录继续保留原源码哈希。

人员排除用例另发现：唯一可见的排除控件可能是没有id的div[role=button]，旧解析器因缺id返回invalid_option。统一选择器生成器现在优先id，没有id则使用当前DOM的精确结构路径；不改点包含项或父级option，不放宽唯一性、可见性或模式。新增无id排除回归，123项离线测试通过；真实排除待针对性重测。

排除重测确认职位已成功设置，但Function列表刷新使结构路径失效，OpenCLI拒绝点击（selector_not_found），没有假报成功。无id控制现在优先精确tag/role/aria-label属性定位，只有无aria标签的展开控制才使用结构路径。保留两次失败回执；123项离线回归通过。该发现说明“找到唯一节点”和“后续定位稳定”必须分别验证。

清空人员字段的实时结果出现了OUT_OF_NETWORK关系路由；旧解析器只接受NAME_SEARCH，因而保守中断为partial/page_changed。适配器现明确接受这两种已观察到的路由，并继续拒绝其他未知类型及外域链接。不能把关系路由当成订阅判断或编造详情可见性。

收集阶段按契约返回partial而非抛异常，因此CLI外层catch不会失效旧execution_context。新增显式partial中断处理后保留已读事实、将context标为unavailable并删除旧快照；受控实际CLI/DOM回执证明旧快照零派发拒绝。缺失快照的错误码为invalid_execution_context，与连接代次变化的context_invalidated分开；校正断言后直接复核已有回执，没有为断言文字再跑浏览器。124项离线测试通过。

受控回放已从临时脚本整理为test/acceptance/开发工具，显式现有依赖路径、合成账号、外网拦截、独立TMPDIR和finally清理；可选择只跑受影响场景，也可对隔离候选CLI运行，证据绑定源码哈希并防止测试期间改源码。23组技术场景补齐异常/恢复/互斥和后置差异，而非重复真实浏览器寻访。新增回执差异和selector_not_found分类修复均先有红色测试。框架的组合夹具因漏UTF-8发生两次候选错误，已记录根因并仅重跑该项；不能把夹具错误算作产品失败。

## 固定候选后的复盘结论（2026-10-20）

本轮的效率问题成立：生命周期缺陷、重复完整诊断、验收启动顺序和夹具预检不足，造成了本可避免的重复。独立双跑是用户要求的模型行为验收，不能当作冗余删掉；应减少每轮内部的无效平台操作。

当前固定候选为 `0.1.0-dev.8`，源码 `81ac508ecbd9a3b4d53f9df19b3030576f8a6566`。构建完成127项离线检查，隔离安装核对42个载荷文件；同一安装上的23组受控技术回放通过，共508次受控协议调用。这里的23组不等于顶层26项E2E全部通过，也不等于独立业务双跑完成。

复盘后的执行要求：

- 每个待验证问题先列已有证据、缺口与所需最小重测范围；已通过字段保留原提交和回执，不因文档措辞更新重开浏览器。
- 技术回放通过后固定候选；业务验收期间禁止改动载荷，必要修复另建候选并评估受影响项。
- 同一账号的浏览器操作串行。命令拥有的临时页必须在结束时关闭，原有用户页保留；持续核对实际标签清单。
- 独立验收开始前检查执行器访问本机浏览器/RPC的权限。第一次dev.8业务运行曾因子进程连接环境报告账号未连接；随后在具备权限的只读调用中确认目标Profile仍连接，受控服务也存活。该失败保留，不算账号订阅拒绝或业务零结果；先修复执行环境再继续原用例，不重跑全部技术矩阵。
- 状态应以固定候选及证据台账为准。历史开发记录只解释缺陷来源，不可把旧的“待验证”段落当成当前待办重新执行。

本次实时标签清单为两个原有页面和一个正在执行验收的临时页面；历史截图中的积压已经清理。临时页的最终回收仍须以该命令完成后的清单核实。
