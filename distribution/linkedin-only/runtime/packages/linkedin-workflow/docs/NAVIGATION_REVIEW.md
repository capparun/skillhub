# 操作流复盘与页面复用（2026-10-21）

## 已证实的问题

1. CLI 每次创建 managedSessionTransport，操作结束 finally 清理。逐家公司启动 CLI 会逐家公司开关标签页。
2. execution_context 缓存套餐/权限，但 accountCheck 仍每次导航 `/feed/` 核对 self URL。因此缓存有效也会反复回首页。
3. 完整检查另外读取 SN 首页、公司搜索、人员搜索、LinkedIn feed 和设置；把完整诊断用作每步前置会增加无关导航。
4. 业务执行应先查看已保存回执；反复运行相同搜索/详情不能扩大覆盖。之前40条卡片是有限采样，快速开关页面不证明筛选完整。

## 本次调整

新增 batch：一次Profile锁、一个插件自建标签页、一个累计调用预算、串行只读操作，finally统一关闭。支持公司/人员搜索和详情。完整检查一次，或使用有效execution_context并核验一次自有URL；后续步骤检查连接代次、当前页面和目标页身份，不逐条回首页。进程内身份租约不序列化、最长5分钟；过期或错误返回部分回执并停止，不自动重试。重复公司详情按ID复用本批首次结果。

新增navigation计数，区分open派发次数、首页访问次数、owned session数；不能把派发当成加载成功。

## 验证

- 修复前导航测试失败：两次操作访问feed两次，预期一次。
- 修复后140项离线测试通过，覆盖三次身份复用、单标签页、一次清理、重复公司复用、身份/连接变化、过期、账号覆盖参数拒绝。
- 完整检查+两家公司：夹具断言共7次导航（5个诊断页面+2个详情），1个session；首页访问共2次（SN首页和LinkedIn feed各一次），后续不再返回首页。
- 2026-10-21真实CLI批次两家详情成功、cleanup closed，33次OpenCLI调用，37.1秒，包含首次完整诊断。私有回执在 `.local/navigation-optimization/batch.json`。本次真实运行发生在navigation计数输出加入前，导航次数依据离线调用轨迹，不冒充真实运行计数。

## 边界和后续使用

- 本地源码已修改；本次未打包或发布。既有dev.10制品不包含batch。
- 独立命令仍逐条自有URL核验并开关标签页；必须选择batch才能使用本优化。
- 同批次不逐条重读自有URL，不能保证检测同一连接内换成同名账号；请勿在批次执行时人工切换账号。身份名、登录状态、连接代次变化会停止。
- 真实验收覆盖批量公司详情；批量人员详情及多条件搜索组合未逐项在线验收。
- 搜索仍从干净搜索页开始，避免残留条件；切换到不同公司仍需导航。当前不保持跨CLI进程浏览器会话。
- 业务工作采用“已有回执去重→批量补证据→模型判断→必要时下一批”，不固定业务筛选规则。
