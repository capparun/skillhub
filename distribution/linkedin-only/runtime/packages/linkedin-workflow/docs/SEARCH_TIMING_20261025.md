# 搜索分段计时验收

新增结构化 timing（毫秒）：account_check、search_setup、collection、cleanup；另按transport方法统计调用次数和耗时，不记录参数、身份或原始内容。阶段计时包含等待，方法计时不等于阶段总时长。CLI启动时间不计入内部total；cleanup包含结束后的本地收尾。适用于带filters的人员/公司搜索。失败调用的方法时间仍累计；失败CLI回执暂未输出timing。

2026-10-25，同账号同关键词、max_pages=1，串行只读：

|limit|模式|总耗时秒|账号检查秒|搜索设置秒|采集秒|返回|导航/首页次数|

|1|完整预检|23.96|18.48|3.54|1.44|1|6/2|
|10|完整预检失败|38.69|未输出|未开始|未开始|未返回|未输出|

|25|复用短期上下文、新鲜身份检查|21.76|5.29|8.84|7.15|25|2/1|

所有成功组stop_reason=result_limit，无采集中断，自有会话关闭。240项本地测试通过。

结论：优先使用已有短期上下文机制，减少重复完整预检；后续优化同批次自有页面复用。完整预检存在偶发account_unconfirmed，需要保留具体失败阶段，不应无限重试。不同模式和单次测量不能直接计算吞吐提升率，也未验证100人翻页，不能给出可靠100人时间承诺。未执行消息或邀请。
