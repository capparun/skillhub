LinkedIn 能力整合设计

日期：2026-10-24｜状态：设计稿，尚未实施或发布

1. 设计结论

用户通过 cskh-linkedin 一个入口表达需求。大模型负责理解需求、选择搜索策略、判断公司或人员是否符合条件；平台适配器负责账号识别、筛选、分页、详情读取等确定操作。

统一入口、任务状态和结果协议，保留现有实现的模块边界。首期不合并仓库、不强行统一 OpenCLI 版本，不重做 Align，不扩大到自动发消息、加好友或保存名单。

2. 当前基础与差距

层面当前基础整合需要补齐
普通 LinkedIncsk/hunter/skills/cskh-sourcing-linkedin，人才寻访流程；X-Ray、scout、Recruiter 路由及人员详情读取从招聘专用入口抽出可复用的平台调用；保留原 SourcingRequest 输入兼容
Sales Navigator本仓库 skills/cskh-linkedin-salesnav；独立 CLI，账号检查、能力发现、筛选、搜索、分页、详情、批处理、导出接入统一任务和结果协议；不重复开发已有筛选器
运行环境普通 LinkedIn 使用产品自己的 OpenCLI launcher；SalesNav 独立运行环境显式选择适配器与运行时，分别校验兼容性
状态与交付两套流程分别处理结果与进度跨渠道去重、搜索覆盖账本、统一报告、可恢复任务

以上来自本地源码检查，不等于已安装环境、线上发布或全部平台操作均已验收。SalesNav 当前为开发版本，工作区有未提交变更；实施前需先固定基线。

cskh-sourcing-linkedin 保留为兼容入口，继续接受已确认的 SourcingRequest，转交统一流程。cskh-linkedin-salesnav 保留为高级专项入口和独立适配器，不再次改名。现有 CLI 保持可用。

建议统一入口与协议由现有 Hunter LinkedIn 产品侧维护；SalesNav 仓库继续拥有其平台实现。协议只有一个版本化来源，适配器通过契约测试接入，避免两边复制后逐渐不一致。此处为归属建议，尚未跨仓库修改。

4. 明确输入与输出

任务输入 TaskRequest（拟议协议 v1）

字段含义
task_id / resume_from新任务标识，或已有任务断点
intentcompany_discovery、people_discovery、entity_read、account_diagnose
account_binding浏览器 profile 标识、期望 LinkedIn 身份；不能只凭 Chrome 显示名称认定账号
criteria条件列表：内容、硬性/偏好、允许的证据与估算方式；具体行业、国家、人数均为任务数据
target目标数量与含义：候选数或符合要求数，必须区分
coverage期望覆盖范围、是否允许部分交付；搜索结果窗口不等于整个市场
budgets页数、请求次数、详情读取量、执行时间等明确上限；触顶留下断点
output默认 HTML 表格和 CSV，按需 PDF；机器 JSON 仅供系统衔接

明确给过的条件直接复用。只对影响执行的缺失信息提问。普通公司研究不强制走招聘 Align；招聘请求兼容已有确认结果，本设计不修改 Align。

任务输出 TaskResult（拟议协议 v1）

- status：completed / partial / blocked；目标未达成不得标记 completed。

- counts：搜索返回数量原文及是否近似、已采集、去重后、已评估、符合、不符合、证据不足数量。

- entities：标准化公司或人员事实、证据来源、采集时间、字段缺失原因。

- assessments：按条件给出符合/不符合/证据不足，估算单独标注依据和不确定性。

- coverage：逐查询筛选条件、读取页数、已收集范围、剩余游标、停止原因。

- artifacts：报告和表格路径；checkpoint：可恢复任务引用。

“符合”是模型基于任务条件得出的判断，不是平台事实。LinkedIn 展示的人数、地区匹配人员数、推算团队人数必须分列，不能直接等同。

普通 LinkedIn 适配器按现有 launcher 命令逐项映射，未实现项返回 unsupported。不能把 SalesNav 的字段名、筛选值或游标直接送给普通搜索。动态选项按账号和搜索类型解析；歧义不能自动选第一个。

工具返回统一信封：操作、状态、数据、证据、错误、覆盖、恢复引用。必须区分已计划、已调用和已读回验证；部分失败不能抹掉已完成结果。

6. 账号、路由与页面生命周期

1. 识别指定 profile 和站内身份，二者绑定后再执行。账号不匹配立即停止，不自动换到其他账号。

2. 根据本次所需操作检查能力，区分 available / unavailable / unknown。Premium 标识不等于 SalesNav 权限，SalesNav 页面可用也不等于某个 API 可用。

3. 大模型提出路由，执行层核验参数和能力。需要高级公司筛选时优先选择满足条件的 SalesNav；普通人员搜索可走普通 LinkedIn。X-Ray 不具备的筛选不能静默丢弃。

4. 能力缺失时明确说明不能满足的条件。替代路线若保持条件语义可继续；改变硬条件或证据要求必须由用户决定。

5. 同一 profile 共用操作队列，防止两个适配器同时导航。复用任务拥有的页面，结束时只关闭任务创建且不再需要的页面。

6. 账号检查结果有有效期；只在过期、身份变化、登录/订阅异常时重新确认。不为每条搜索或公司详情回首页。

7. 页面上下文和短期授权检查按适配器隔离，不能冒用另一适配器的 execution_context。实现跨适配器队列前，不允许同 profile 并发。

8. 登录挑战、访问限制或权限拒绝触发停止和可读说明，不能以更换通道规避限制。

订阅名义额度、平台可见余额、本地调用计数分别记录；没有可见余额时返回未知，不能用名义额度减去本地调用量伪造官方余额。

7. 搜索覆盖与调整策略

每个查询组合都写入账本：平台、账号引用、条件指纹、返回数量原文、近似标记、已读页、唯一结果数、下一游标、停止原因、模型下一步判断。

模型根据结果数量、重复率、符合率、缺失证据和剩余预算决定继续翻页、细分查询或提出放宽条件。执行层只执行决定并保存回执，不硬编码“少于多少就放宽”“只取第一页”或“最多三轮”。

- 数量适中且预算允许：读完可访问结果窗口。

- 数量超出窗口或预算：按有意义的维度拆分，记录子查询与覆盖关系，跨查询去重。

- 数量为零：确认查询实际生效、页面加载完成；推荐公司不能混作搜索命中。

- 达到目标但未读完：可以按任务约定停止，但报告须标记目标已达成、搜索覆盖未穷尽。

- 预算耗尽或平台阻断：保存已有结果与断点，不从首页重跑已完成查询。

不同平台的返回总数不能简单相加。跨平台实体合并依赖明确 ID、直接映射或可核对证据，不能只凭同名；SalesNav 标识按不透明标识处理。

8. 面向用户的结果

公司表：公司、主营业务、总部、全球规模、目标地区团队估算及依据、自有跨国实体/团队证据、符合情况、来源链接。

人员表：姓名、当前公司/职位、地点、相关经历、符合理由、证据缺口、来源链接。

报告首先展示已符合条件的结果、实际数量和完成状态。证据不足项另表说明具体缺口，不在主表反复显示笼统“待核实”。不符合项保留可追溯记录。默认交付表格，不把 JSON 展示给最终用户。

例如“东南亚 MedTech 公司”只是一次 TaskRequest：行业、规模、地区、跨国实体要求和允许估算的口径均随用户需求变化，不能写进 Skill 固定规则。

9. 实施顺序与验收

阶段工作验收出口
0 固定基线整理现有未提交代码，记录两个运行时、命令和版本边界可重复的基线测试与能力清单
1 统一协议TaskRequest/Result、事实/判断分离、错误和覆盖契约合成夹具验证；未知、部分成功不能被包装成成功
2 接入适配器包装现有普通 LinkedIn 与 SalesNav；能力路由、身份绑定、共享队列原 CLI 不退化；不重复主页导航；不跨账号
3 统一 Skill 和报告新入口、旧入口转交、恢复账本、HTML/CSV同一需求在支持路由上得到一致格式和可追溯结果
4 受控实测与交付少量只读账号实测、兼容性清单、独立版本回滚区分本地/安装/实测/发布状态，再决定上线

核心端到端用例：

1. 普通账号无 SalesNav：返回明确能力缺口，不宣称高级筛选已执行。

2. 有 SalesNav 的公司搜索：筛选读回一致，返回数量、分页和报告对应。

3. 已确认的招聘 SourcingRequest：旧入口可用，无重复需求确认。

4. 两个 Chrome profile：绑定目标身份，不串账号、不共享账号证据。

5. SalesNav UI 可用但调用失败：区分权限和执行故障，不把接口失败判成未订阅。

6. 多页搜索与中断恢复：继续原断点，不重复已完成页；游标失效明确处理。

7. 超出可访问窗口：拆分并去重，报告不能声称全量市场覆盖。

8. 允许人数估算：展示观察值、估算依据和不确定性，不冒充精确人数。

9. 用户中途修改条件：保留原事实，重新评估；查询改变时不复用旧游标。

10. 两平台读取同一实体：有证据才合并；同名实体不误合并。

11. 连续搜索和详情：同 profile 串行、复用页面，无每步首页检查；只回收自建页面。

12. 用户只要求搜索：不会发送消息、连接邀请或保存名单。

10. 非目标与待实施项

不在本轮修改运行时代码、安装全局 Skill、调整账号、发布或合并仓库。普通 LinkedIn 的完整命令映射、跨适配器锁、协议实现和实时端到端验证属于后续开发，不能把本设计当作已实现能力。
