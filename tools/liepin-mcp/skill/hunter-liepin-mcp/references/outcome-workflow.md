# 以找到值得跟进的人为目标

## 任务契约

复用已确认JD、允许例外、目标组和范围。开始前只补会改变判断的歧义；无歧义直接继续。明确停止条件（完成约定搜索范围、用户指定数量、预算到达或平台受阻），不把详情配额或生成报告当作业务目标。数量未指定时先完成已批准轮次，输出覆盖与下一轮建议，不无限搜索或承诺找到固定人数。

标准分四层：硬性要求、加分项、允许例外、待沟通事项。用户已经授权按确认标准判断并收藏时，不逐人审批；专业判断与引用依据可复核。仅依据职位相关技能、经历与资格，不用敏感属性、关键词计数或不透明分数决定人选。不作最终录用决定。

## 搜索和详情覆盖

先提出职位别名、技术词、预期噪声和要验证的问题。公共研究只能形成假设；实际命中效果取自平台。每轮读取列表逐条记录：明确无关跳过及理由、需要详情、已有关联详情复用。相关或信息不足者进入持久队列，无固定3份限制；不因未读或未提及认定不具备。补读须在现有授权、预算及来源页有效范围内。

对所有进入详情的人使用当前已确认JD的同一组关键标准，记录原文证据及supported/contradicted/unknown。核实本人承担的职责、岗位必需能力、相关经历时间线、成果和资格，再记录该岗位的加分项及沟通事项。具体技术、行业、成果形态均从本次需求推导，不沿用其他岗位的核实维度。部分可见时列具体限制，不为补齐字段索要或解锁。

### 每轮收益决定下一步

开始前区分开发验收范围和实际寻访范围。验收用的首页数量、详情数和搜索次数只适用于对应测试，不能变成正式寻访的默认停止条件。实际任务沿用用户已授权的范围与账号预算，缺少数量目标时制定有界探索计划并说明，不默认为无限采集。

每轮保存：实际查询与筛选、列表量、新增去重人选、已读详情、值得跟进与已核实收藏量、未处理队列、主要噪声、剩余额度和下一决定及理由。需要平台权益或耗时数据而无法观察时标记未知，不把程序操作计数当作平台权益余额。

- 当前结果仍有未处理且可能合适的人，优先处理队列，避免不断开新搜索。
- 当前结果偏离标准，按原因修改一个主要检索维度：职责词、技术词、相关资历或企业方向；记录预期改善，再用下一轮结果验证。总工作年限不等于对口经验，筛选后仍核时间线。
- 有新增价值且还有已授权范围时继续；重复增多或方向偏差时调整；达到用户目标、合理策略用尽或触及预算/平台限制时停止。不能仅因成功收藏两位或生成报告而停止，也不能为了更多数量降低标准。
- 明确按当前标准不跟进的对象记录理由即可，不全部转交用户。只有需要改变标准或允许例外的决定才集中请用户校准；材料缺失不写成事实上的不具备。

本地收口应记录真实停止理由。单轮覆盖完成并不意味着整个寻访目标已达成；尚有必要的后续轮次时保留partial与下一轮计划。

## 收藏与反馈

区分“值得跟进”与“全部满足”。已授权范围内，依据明确技术证据作辅助判断；关键门槛未知保留具体问题，明确冲突不得按完全符合描述。标准发生真正冲突或边界无法决定时集中请用户校准；不因每人都有待沟通项增加逐人审批。

当前标准中硬性要求被明确反证、或排除项有明确支持证据时，先记为clarify或not_pursued，不进入follow_up。用户确认允许例外后，更新相应标准、重新确认契约并重新核实受影响人选；仅填写gaps不能豁免门槛。未知信息仍可按已确认的跟进策略处理，不等同明确不符合。

写前核对稳定身份、准确目标分组、已有状态、授权和剩余额度。目标组不存在不擅自创建或选未分组。已在该组则跳过写入。收藏后回读目标组归属，不能以全局已收藏代替入组成功。confirmed跳过；unknown只核对不写；planned或有证据未生效者才进入写入。未知不能换ID重试。

反馈校准更新任务内标准解释版本，保留原依据及受影响人选；不得自动取消原收藏，取消需对应授权。共享Skill只保存通用流程，不保存客户JD或候选资料。

## 完成与恢复

每处理一人判断：还有未处理项且范围预算允许则继续；否则汇总。范围完成但目标未达时给出下一轮关键词与理由，不擅自增加搜索。平台验证、限流、白屏或未知动作立即转核对与部分交付，不能换工具绕过。

只通过MCP Site Adapter执行浏览器业务，不调用CUA作为必需步骤或备用通道。先区分本机IPC权限、宿主连接、页面状态；沙箱内“无宿主”不能单独证明扩展未连接。页面变化重新观察，旧CSS及序号不能跨集合沿用。

交付正文：覆盖范围、值得跟进的人及依据、收藏准确分组及回读结果、关键缺口、未处理项和停止原因。完整简历放独立详情HTML，原始任务与审计记录放独立JSON。每人可追溯到原观察、标准版本和操作回执。程序测试、真实采集、收藏闭环和视觉验收分别声明。

## 可执行的本地台账

以下都是local.mjs的task模式，不操作浏览器，也不替代原有authorize/grant/site scope。

- `sourcing-configure`：input={goal:"favorites"或"research",groups:[准确分组],confirmedBy:真实确认人,confirmedAt:真实确认时间,authorization:用户授权原话,stopCondition:本轮停止条件}。绑定当前标准摘要，保留修订历史。
- `list-review`：input={observationId,disposition:"needs_detail"或"reuse_detail"或"skip_unrelated",reason}。引用实际列表观察并记录处理理由。
- `evaluate`：原有逐项证据接口；每项必须整理具体依据或缺口，不以自动填充的“尚未核实”代替统一复核。
- `sourcing-decision`：input={candidateKey,decision:"follow_up"或"clarify"或"not_pursued",reason,gaps:[具体未知或冲突],group,reviewer}。要求当前有效完整条件核对；跟进需要至少一项职位支持证据。标准或简历证据变化时旧处理依据过期，不能自动沿用。
- `sourcing-progress`：只读输出人选处理、当前评估版本、收藏回执及未核实状态；不会自动执行收藏或宣布业务完成。
- `sourcing-close`：input={status:"complete"或"partial",reviewer,reason,coverage,coverageConfirmed:true或false}。核对人说明已完成的搜索范围与停止原因；有未核对操作、待校准人选、缺失详情或跟进人选分组未核实时，只能部分收口。完整收口要求确认覆盖且无这些阻塞。记录绑定当前证据，后续标准、观察、判断或操作改变会过期；不改变账号授权、不代表最终录用或市场人才已找全。
- `budget-preflight`：input={operations:本批次尚需操作总数}，只读检查任务与同账号剩余额度及未确认操作，不扩额、不预留、不授权。多位收藏前汇总每位重开+收藏两笔，另加明确授权的建组操作；已完成回执不重计。每位favorite-list也会在打开前检查自身所需两笔或三笔。预检后其他会话可能消耗额度，执行时仍逐笔核对；发生不足时保留已完成结果。

收藏继续调用正式favorite Adapter；全局已收藏但目标组未知时不能计为目标组确认。确认时间来自真实对话，不用脚本运行时间冒充用户发言时间。历史收藏回执没有groupVerified时保留未核实，不自动升级为成功。

保存前选择分组与保存后“已收藏”只证明已选择并保存，回执为saved-state-readback，不能独立证明归属。使用favorites读取已绑定收藏列表；只有页面唯一选中组名称、列表数量相符且条目可见链接解析出稳定身份时，才记录favorites-list-readback归属证据。该回读须晚于此人的最近收藏/取消操作；没有读到人不等于不在组内（可能在未读范围）。旧版仅有groupVerified布尔值的回执不当作独立归属证明。favorites可带group指定准确名称，只点击唯一可见的分组节点并回读所选组，不翻页、不修改收藏。请求授权payload也须包含group；找不到、重名或回读不一致时停止并保留待核实，不默认选其他组。

## 从当前列表完成收藏

已读详情已关闭时，使用`favorite-list`（需发现当前schema），参数为file、tab_id、observation_id、group、operation_id、open_operation_id。它要求当前有效的follow_up记录及稳定身份。写前分别授权两笔请求：

1. favorite-open payload={observationId,observationHash,page:tab_id,purpose:"favorite",favoriteOperationId:operation_id}，用于再次打开同一位已核实人选；不同于初次详情采集。
2. favorite payload={observationId,observationHash,page:tab_id,resumeId,action:"add",group}。

两笔计入原任务与同账号预算。打开回执完成后才执行独立收藏操作；同一调用核对新详情身份并持有关闭权限，结束关闭详情返回原列表。收藏完成重复调用仅取原回执，不打开页面；未知写入不新开页面重试。已完成打开但调用中断时不复用旧标签关闭权限，先核对，按既有有限重试流程处理。此接口不新增搜索，不补读简历全文，不自动创建分组。

`favorite-open`是受控的收藏详情访问类型，与初次`detail-open`分开计数；站点去重仍绑定观察ID和hash、不随标签ID变化。失败的预算预留不会派发浏览器动作，先用browserStarted:false证据核对并恢复任务，不能删掉失败记录。

收藏访问去重同时绑定实际收藏操作ID；只有原收藏已核实未执行并获有限重试时，新的收藏操作ID才可对应新的访问请求。打开前先校验收藏请求授权及重复状态，不能借新访问ID绕过未知写入。

### 明确授权的新建分组

目标组缺失时询问准确名称或是否创建，不能自动选未分组。用户明确批准创建后，`favorite-list`可带`create_group:true,group_operation_id`；必须单独登记`favorite-group-create`请求，payload={name:准确组名,parent:"我的收藏"}。已有组直接复用，创建只在“我的收藏”根节点进行。先只读识别分组树，再点击根节点“添加子节点”、填写唯一可见编辑框、核对名称、点击观察到的确认控件、回读实际分组存在后才收藏。不能猜测Enter、不能创建同名重复组。创建结果未知先核对，不重试或继续收藏。取消/删除组另需明确授权。

### 收藏前检查完整栏目和明确求职约束

收藏前同时核对工作、项目、教育、技能、自我评价、求职意向和附加信息；不能只读取技术经历后作决定。以JD明确的工作地点、工作方式等职位约束，与候选人明确声明的可接受条件作对照。当前居住地不同不等于拒绝迁移；“不接受某工作地点”等明确原文冲突则不能只写为待沟通后继续收藏，也不能据此推断其他人选的意愿。

明确的联系偏好或拒绝联系声明单独记录，不把技术适配当作联系许可；实际联系始终受用户授权和平台限制约束。是否进入内部跟进池按本任务策略判断，保留原文及理由，不把拒绝联系自动推断成技术不合格。

发现遗漏后保留原判断、原始引用和收藏回执，追加纠正记录并更新报告。已经发生的错误收藏须明确列为待纠正，不把本地修改决定说成平台已移除；只在取消授权覆盖时纠正对应本轮写入，不能清空整组或改动此前其他收藏。技术适配与求职约束分别呈现，不用技术优势覆盖已知的岗位地点冲突。

## 独立收藏工作页核验

已绑定搜索页且要保留结果时，使用 favorites 的 `workspace:true`；`tab_id` 指向保留的原页面。授权请求须明确包含 `view:favorites`、原页面、limit、准确group和workspace:true。Adapter在同一会话新建固定的人才管理页，读取指定分组后关闭自建标签并返回原页面；不会导航或关闭用户原标签。已有收藏页可继续使用默认workspace:false。

工作页读取与关闭均有用户视角日志。失败保留操作状态，不能换操作ID自动重放；先核对未知效果。只有准确组名回读和稳定身份出现在可见收藏列表时，才确认组内归属；保存按钮成功不替代组内核验。此入口须配套支持openFavorites生命周期的候选宿主，旧宿主明确报错，不切换CUA。

## 按内容阅读与滚动

用户要求较慢阅读时，不能只增加两次打开之间的空等。列表先查看当前可见卡片，再按需要滚动到下一屏或目标卡片；详情按工作经历、项目、教育、技能、自我评价及附加信息逐段核对，长简历应有更长的阅读时间和必要滚动。避免打开后立即关闭并连续跳转。已保存内容优先本地分析，不为表现阅读重复访问真实页面。

滚动服务于查看内容与定位，不制造无意义鼠标动作、不用随机动作伪装或宣称可避免检测。阅读时长、滚动和展开应由实际内容决定；区分页面停留与已完成的内容分析。用户视角日志写明阅读栏目、滚动方向及结果，不能把后台全文采集描述成逐屏人工阅读。若当前执行器仅支持采集间隔，明确记录该能力差距，完成分段阅读流程开发后再声称已支持。

## 平台筛选必须落实

每项已确认岗位条件分成：平台准确筛选、详情核实、沟通核实。记录字段、真实选项、匹配方式、不能设置的原因及原始要求。不要把资历总年限当成对口工作年限；不要把当前城市当成到岗意愿；不要以硕士筛选删除已批准的本科量产例外。年龄、性别等敏感属性不作为招聘判断或默认筛选。

先只读回查选项与当前值，确认平台选项语义；需要展开控件才能发现时使用已授权的Adapter页面操作并记录。合成测试里的字段值不能冒充真实页面标签。单选“5–10年”不能代表“5年以上”，“本科”也不能自动当作“本科及以上”；若不能准确表示，使用已核实的宽口径或分轮覆盖并去重，剩余要求在详情核实，明确覆盖缺口。

每次换关键词必须继承已确认的筛选基线。搜索轮次输入完整包含关键词和筛选字段，不能只在之前prepare一次后假设搜索会保留。筛选回读失败则停止该轮；结果为空先检查条件交集，不自动放宽用户硬门槛。正文交付同时列出实际平台条件与仅在详情判断的条件。

### 阅读节奏与轮次收口

默认采用重点核对节奏：列表仅在目标未入视口时滚动，卡片短暂停留；详情默认最多检查3屏，每屏按可见文字量停留1–4秒，不对每屏固定等待8秒。长文和疑点优先用已保存资料分析，确需继续核对页面时再安排有界补读。该上限只限制默认可见检查，不限制保存的账户可见全文，也不表示所有栏目已经逐屏看完。页面加载、遮罩消失、身份验证和异常停止不因提速省略；停留时长不作为规避检测的保证。

进入下一搜索前，先处理本轮已读资料的判断和可执行收藏闭环。尚未处理的条目必须明确记录为待评估、待核实或延期及原因；不得仅因搜得更多而遗失上一轮可能合适的人。切换结果集合后旧卡片定位失效，不用旧CSS或序号执行收藏。批量详情默认按当前列表保存顺序阅读，明确优先级时可指定顺序，避免无必要的上下往返滚动。

平台选项需展开探索时使用 `prepare` 的 `options_only:true` 及对应只读探索授权，仅打开选项并关闭，不设置条件或搜索。`verify_only:true` 用于回读当前状态，两者不能同时使用。搜索计划可用 `composeKeywordRounds` 继承基线，或用 `composeCoverageRounds` 按真实单选区间生成有界覆盖组合；计划生成不等于已执行，覆盖完成必须逐轮绑定实际回执。

收藏或取消后再次读取同一分组时，使用 favorites 的 `after_operation_id` 指向本任务同组已完成的写入回执；对应授权 payload 包含 `afterOperationId`。这会保留旧读取并产生写后新核验，不靠更换limit、标签或操作ID绕过重复保护。缺少完成回执、组名不一致或写入未知时，先停止核对，不能使用此参数重试写入。
